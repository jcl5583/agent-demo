# agent-demo

跟着项目实战路线做的 Agent 工具调用练习：用 function calling 让模型自己决定调用哪个工具。

## 当前支持的工具

| 工具 | 作用 | 参数 |
|---|---|---|
| `add` | 两个数相加 | `a`、`b` |
| `get_weather` | 查询城市**实时**天气（Open-Meteo API） | `city` |
| `get_employee` | 查询员工部门与月薪（SQLite） | `name` |

## 跑起来

1. 复制 `.env.example` 为 `.env`，填入自己的 API Key
2. `pip install -r requirements.txt`
3. `python demo.py`

## 能看到什么

问「3 加 5 等于几」，模型会调用 `add`；
问「北京天气怎么样」，模型会调用 `get_weather`；
问「3 加 5 顺便看北京天气」，模型会一次调用两个工具；
问「先查北京、再查上海，告诉我温差」，模型会自己走三轮（查北京 → 查上海 → 算差值）；
问「张伟的月薪是多少」，模型会调用 `get_employee`；
问「先查张伟的部门，再看北京天气」，模型会自己串起两个不同来源的工具。

## 当前能力

- 多个工具由模型自行选择，支持一次并行调用多个
- ReAct 循环：模型可连续多轮调用工具（最多 5 步）
- 工具失败自动重试，重试仍失败则降级回答
- 请求级超时保护
- 每次运行记录完整轨迹（`traces/traces.jsonl`），含每轮工具调用、参数、结果与耗时
- 回归集 + 自动评测脚本
- 天气工具接入 Open-Meteo 公共 API，返回真实温度与天气状况
- 三个工具覆盖三种类型：计算（`add`）、外部 API（`get_weather`）、本地数据库（`get_employee`）

## 容错设计

| 情况 | 处理方式 |
|---|---|
| 工具抛异常 | 自动重试（原始 1 次 + 重试 2 次） |
| 重试仍失败 | 把错误作为工具结果回传给模型，让它降级回答，而不是抛给用户 |
| 模型调用了不存在的工具 | 拦截并返回提示，程序不崩 |
| 查询对象不存在（城市/员工） | 直接返回“查不到”，不重试——这类错误重试也没用 |
| 请求卡住 | `timeout=30`，不会无限等待 |

核心思路：**工具的失败也是一种结果，要告诉模型，而不是让程序崩掉。**

## 轨迹记录

每次运行会在 `traces/traces.jsonl` 追加一行 JSON：

| 字段 | 含义 |
|---|---|
| `id` | 本次运行 ID |
| `question` | 用户问题 |
| `started_at` | 开始时间 |
| `steps` | 每一步的工具名、参数、返回结果、耗时 |
| `answer` | 最终回答 |
| `status` | `ok` / `max_steps` / `error` |

写入放在 `finally` 里，即使中途抛异常也会落盘。`traces/` 已加入 `.gitignore`。

## 评测

`eval/cases.json` 里是 23 条回归用例，覆盖六类场景：纯算术、纯天气、数据库查询、多步推理、并行调用、不需要工具。

```powershell
python eval/run_eval.py
```

判定标准：

- 期望用到的工具**都出现了**（允许多调，不允许少调）
- 回答里出现期望的关键词
- 运行状态为 `ok`

当前通过率：**待重跑**（加入数据库工具后需重新确认）

模型输出有随机性，同一份代码跑两次结果可能不同，所以看的是**多次运行的稳定性**，不是单次满分。

## 踩过的坑

1. **模型不调工具时 `tool_calls` 是 `None`，不是 `[]`。** 直接 `for c in msg.tool_calls` 会抛 `TypeError`，必须先写 `msg.tool_calls or []`。
2. **工具抛出的异常会直接崩掉整个循环。** 必须用 `try/except` 接住，转成 `tool` 消息回传给模型，否则用户看到的是 traceback。
3. **重试没有退避。** 现在三次重试是立刻重发的；生产环境应按 0.5s、1s 递增等待，否则服务真挂了会被打得更惨。
4. **Windows 下写文件不带 `encoding="utf-8"` 会乱码或报错。** Python 默认用系统编码（GBK）。
5. **评测标准写太严，会把正确结果判成错误。** 例如要求工具集合完全相等，模型多调一个 `add` 算差值就被判错了。
6. **相对路径跟着“工作目录”跑，不跟着代码文件跑。** `TRACE_DIR = "traces"` 在 PyCharm 里运行 `eval/run_eval.py` 时被解析成 `eval/traces/`，评测脚本读的却是项目根，导致 20 条全部误判成“没用工具”。写文件路径一律用 `os.path.dirname(os.path.abspath(__file__))` 拼绝对路径。
7. **大段内容靠粘贴会静默截断。** 复制不全不会报错，文件照常保存成功，只是少了一截（本 README 就发生过一次，整节“踩过的坑”消失）。粘贴后必须检查文件末尾和代码块是否闭合。
8. **URL 里不能直接放中文。** 城市名必须 `urllib.parse.quote()` 转义，否则请求直接失败或返回空。
9. **错误要分类，不能一律重试。** 城市不存在属于“永久失败”，重试三次也查不到，应直接返回提示；网络超时才是“临时失败”，值得重试。
10. **`with sqlite3.connect(...)` 只提交事务，不关闭连接。** 必须显式 `conn.close()`（或 `contextlib.closing`），否则连接越积越多，最后数据库被锁。
